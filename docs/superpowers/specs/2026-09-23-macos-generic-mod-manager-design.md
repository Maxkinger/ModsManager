# mayflyMods macOS 通用管理版设计

日期：2026-09-23

## 目标与范围

以 mayflyMods 的 Electron、Vue 3 和 TypeScript 代码为基础，在 `Maxkinger/ModsManager` 发布非官方 macOS 移植版。首版面向 Intel 和 Apple 芯片 Mac，用户可以手动指定一个游戏目录和 Mod 安装相对路径，在该目录中导入、预览、安装、卸载 Mod，并使用备份、恢复与内置 URL 下载。保留原项目署名、许可证与特殊使用声明。

本版的游戏支持范围是“用户指定的通用目录规则”，不是对上游 144 个 Windows 游戏预设的 macOS 兼容承诺。macOS 界面应引导用户添加自定义游戏；尚未验证的 Windows 预设不得被当成 macOS 已支持游戏。Steam 自动定位、Windows `.exe` 启动、游戏专用 `AppData`/Documents 规则、依赖 PowerShell/.NET 的规则和 aria2 可选引擎不属于首版 macOS 验收范围。Windows 原有流程仍保留。

用户要求通过 GitHub 公开提供未签名下载包。首版使用 GitHub Release 分发两个架构的 DMG，不配置 Apple 签名和公证。发布说明必须准确提示 macOS 的首次打开限制与 Apple 的“仍要打开”步骤；不能宣称下载后可无提示直接运行。仓库当前本机 GitHub 凭证无效，推送与实际 Release 需在可写入 `Maxkinger/ModsManager` 的凭证恢复后执行。

## 方案选择

1. **单一 Electron 代码库，平台适配层（选择）**：复用界面与文件操作，在少数平台边界分流。可以保留 Windows 版并逐步加入游戏适配。
2. macOS 专用精简分支：短期改动可少一些，但 Windows 修复和通用功能会长期分叉。
3. SwiftUI 重写：能获得原生界面，但需重做整个状态管理、下载和安装引擎，超出首版目标。

## 组件与数据流

### 路径与平台

`electron/preload.ts` 向渲染进程提供只读平台标识。新增纯 TypeScript 路径工具，集中完成 `dirname`、`basename`、根目录与相对路径拼接；Windows 使用反斜杠，macOS 使用正斜杠。`src/stores/library.ts` 和 `src/App.vue` 中参与真实文件操作的手写路径拼接改用工具。主进程继续使用 Node `path` 模块，并在安装计划、部署和卸载前维持目标路径的根目录检查。

保留现有 JSON 数据格式与 Windows 路径值，不自动改写旧记录。macOS 新建的记录存储 POSIX 绝对路径。用户数据仍放在 Electron 的 `userData` 目录；Mod 文件放在用户选择的存储目录。

### macOS 游戏入口

macOS 默认通过目录选择器添加自定义游戏。用户可设置游戏根目录和可为空的安装相对路径；应用利用现有自定义 adapter 生成安装计划。macOS 暂时不提供 `.exe` 选择和通过 `.exe` 启动游戏的入口。预设列表在 macOS 明确标成未适配，不能从其 Windows 安装规则直接执行部署。自定义游戏若没有可验证的启动目标，播放按钮不执行猜测性启动，并给出明确提示。

### Mod 文件操作

保持导入文件夹、单文件、ZIP、7z、RAR，安装计划预览、冲突阻止、部署记录、卸载和回滚。验证 `7zip-bin` 的 macOS 可执行文件在打包后的路径和执行权限；需要时将其作为包外资源放入 `.app`。对测试目录中的真实文件执行安装与卸载，确认不生成含反斜杠的文件名，也不删除游戏目录之外的文件。软链接安装应仅在目标卷支持且测试通过时启用；否则给出可理解的错误并允许复制安装。

### 下载和备份

内置下载引擎生成 macOS 路径，可下载自定义 URL 并自动导入。备份和恢复继续使用项目现有接口，但输出路径改用跨平台工具。可选 aria2 在 macOS 首版隐藏或禁用，避免提示用户选择 `aria2c.exe`。游戏专用存档目录规则待逐款验证；通用版先支持用户选定目录的备份和恢复。

### 构建与发布

在 `package.json` 增加 macOS 构建命令与 DMG 目标，提供 macOS 图标，并明确关闭自动签名与公证。GitHub Actions 增加 `macos-latest` 工作，使用锁文件安装依赖、运行类型检查与相关检查，再分别构建 arm64、x64 DMG。标签触发的发布工作将两个 DMG 上传至 `Maxkinger/ModsManager` 的 GitHub Release；普通提交仅上传 Actions 构建产物。保留 Windows 工作流。

README 写明非官方移植、已验证与未验证的功能、两种架构的下载选择、未签名应用的首次打开步骤，以及原作者署名和授权文本位置。发布时不覆盖或改写上游 `LICENSE`。

## 错误处理

- 未设置存储目录或游戏目录时，阻止导入与安装并说明缺失项。
- 安装目标超出用户指定目录、已存在冲突、压缩包条目越界或软链接失败时，沿用计划、阻止和回滚机制，并验证目录保持原状。
- macOS 用户点到仅适用于 Windows 的预设或策略时，明确提示暂未适配；不尝试写入模拟的 `AppData` 路径。
- 下载、备份和恢复失败时保留现有错误与日志，不把失败标成完成。

## 验收

1. macOS arm64 开发运行与打包后的 `.app` 可启动；Actions 能生成 arm64 和 x64 DMG。
2. 在临时测试游戏目录中，创建自定义游戏、导入 Mod、预览目标、安装、卸载后，文件状态与预期一致；压缩包和软链接路径分别验证。
3. 自定义 URL 下载、游戏目录备份和恢复使用 POSIX 路径并完成一次实际读写。
4. `npm run typecheck`、相关现有检查与生产构建通过；Windows 专用行为没有因路径改动被移除。
5. Release 文档如实注明“未签名、未公证”、安装步骤、首版功能边界与原项目授权。

该设计不承诺每款游戏的 Mod 规则正确，也不让 Windows 专属游戏在 macOS 原生运行。后续逐款适配需要对应游戏的 Mac 安装、存档与 Mod 目录样本。
